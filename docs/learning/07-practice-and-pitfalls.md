# 07 练习与易错点：每次只验证一件事

这些练习尚未替你执行或改入业务代码。前两项不要求改文件；后续练习也只改一个明确目标，便于你观察结果和撤回自己的改动。

## 练习一：把一个组件讲明白

阅读 [Check.vue](../../src/components/Check.vue) 与 [PasswordLogin.vue](../../src/pages/login/PasswordLogin.vue)，画出 `isAgree → modelValue → 点击 → update:modelValue → isAgree`。

预期掌握：说明状态由父组件持有，并解释为什么子组件发事件就能让父组件更新。不要尝试真实登录，这个页面没有完成真实登录链路。

## 练习二：不改代码，跟踪一条请求

按第 02 篇启动项目，在浏览器 Sources 中给 `SlideList.getData` 和推荐 Mock 回调下断点。打开首页，记录第一次请求的 `start`、`pageSize` 和返回长度，再观察一次加载更多。

预期掌握：下一次 `start` 来自已加载数组长度；`pageSize = 10` 不保证每次都返回 10 条；Axios Mock 请求与静态文件请求并不是同一类网络活动。

完成标准是能指出是哪一行更新了 `state.list`，以及该行执行前后的数组长度，而不是只说“页面出来了”。

## 练习三：只改一处界面文字

目标文件：[BaseFooter.vue](../../src/components/BaseFooter.vue)。把模板里的“消息”暂时改成“消息中心”，不要动 `tab()` 或路由。

预期：底部显示文字改变，点击仍去 `/message`。这能帮助你分清“标签文案”和“导航逻辑”。完成后用编辑器撤销自己这一次改动，确认差异消失。

这个练习不调整样式。后续修改界面时沿用现有 Tailwind 原子类，不重新增加业务样式类或 Less 文件。

## 练习四：观察昵称副本与共享状态

通过“我 → 编辑资料 → 名字”输入新昵称。先观察不保存返回的路径，再观察保存返回的路径，最后刷新浏览器。

按源码预期：输入时改的是局部副本，保存时才改 Store，刷新后重新读取初始资料。若实际表现不同，先核对编辑页初始化、缓存和 `isChanged`，不要立刻归因于 Pinia。

完成标准：能指出“写副本”“写 Store”“读取静态数据”分别发生在哪里。这个练习不需要改源码，也不会修改仓库里的用户 JSON。

## 练习五：做一个最小调试页

等前四项完成，再自行新增一个小页面，例如 `src/pages/test/Learning.vue`，使用第 03 篇的完整示例：勾选后允许“记录一次”，点击后计数增加。然后在 [routes.ts](../../src/router/routes.ts) 末尾添加 `/learning` 路由，不重排已有记录。

需要触达的范围只有新页面和路由注册；复用 `Check`、`BaseButton`，不用添加依赖或新样式系统。

验收至少包含三步：未勾选不能增加次数，勾选后每点一次加一，取消勾选后计数保持原值且不能继续增加。还要确认首页和返回导航没有因新路由受影响。这些是待执行的检查，不是本次已通过的测试记录。

这一项的完成标准是：你能写出一个小组件的状态与事件，并把它接到现有应用里。

## 练习六：用断点理解切换，先不改手势算法

在 `SlideVerticalInfinite.vue` 的 `touchEnd` 和 `BaseVideo.vue` 的 `click` 中观察一次切换。分别记下 `localIndex`、广播的 `uniqueId` / `index` / `type`。

预期掌握：手势先决定索引，再通知播放器；“DOM 中存在一个视频”和“这个视频当前播放”是不同条件。断点会暂停时间敏感逻辑，观察异常时先取消断点再复现，不要据此直接判断动画有问题。

## 源码里哪些写法先理解，不照抄

以下分为“直接确认的实现”和“需要运行验证的影响”。这不是完整代码审计，本次没有顺带修复。

### 1. 错误返回可能被重新标成成功

[request.ts](../../src/utils/request.ts) 的响应拦截器返回普通失败对象，外层 `.then()` 又固定设置成功。影响按源码可推导，具体页面错误表现需运行复现。学习请求封装时应保留正确的成功/失败语义，不能只处理数据解包。

### 2. 推荐总量与文件数量不一致

本地确认 6 条初始记录加 832 条追加记录，接口却写死 844。列表达到 838 时，`totalSize === list.length` 仍不成立，可能继续请求空页。这里确认的是计数与条件差异，实际滑动到尾部的表现尚未实测。

### 3. 资料编辑的字段和名字存在不一致

[EditUserInfoItem.vue](../../src/pages/me/userinfo/EditUserInfoItem.vue) 的简介输入绑定 `signature`，`isChanged` 却主要比较 `nickname`、`desc`、`unique_id`。两个编辑页面又都声明了 `EditUserInfo` 组件名，而缓存按名称排除。学习时先走昵称分支，别把其他分支当成已经完整验证的范本。

### 4. 事件总线清理可能影响其他订阅者

[bus.ts](../../src/utils/bus.ts) 的 `off(type)` 会删除这一类型的全部回调，`offAll()` 会清空所有事件。首页卸载调用了 `offAll()`。若只是清理自己的监听，应理解 `off(type, callback)` 的区别。

另外，当前 `once()` 只是替换该事件的回调数组，`emit()` 没有在触发后删除它；不能仅凭函数名认为它实现了“只执行一次”。

### 5. 直接修改传入对象和全局点击代理需要谨慎

[ItemToolbar.vue](../../src/components/slide/ItemToolbar.vue) 会修改传入记录的嵌套计数，再通过事件更新条目；[main.ts](../../src/main.ts) 还代理了 `HTMLElement.prototype.addEventListener`。这些做法影响范围比一个普通点击处理函数大，初学时先练习明确的父传子、子发事件。

### 6. 本地存储并不代表有完整持久化方案

用户资料 Store 没有自动持久化；部分选择页面显式用 `localStorage` 暂存。学校编辑页面还调用 `localStorage.clear()`，它清理的是该来源的全部本地存储。不要把这种清理方式复制为“只清理一个表单”的通用实现。

## 页面不对时，按哪里排查

- 无法启动：先看终端第一条错误，核对根目录、依赖和 pnpm 配置，不先改 Vue 页面。
- 有界面但无列表：看 `active` 是否为真，是否发出了 `refresh`，Mock 是否命中，数据是否具有 `list` 字段。
- 有标题和封面但视频黑屏：单独检查媒体地址请求、浏览器播放限制和 `video` 事件，不能只看业务接口。
- 点击似乎无效：先确认是否调用 `_no()`，再看 `loading` / `disabled`、自定义 `v-click` 和 `window.isMoved`。
- 返回后数据没有重新加载：先判断组件是否被 `keep-alive` 保留，检查激活回调而不只看挂载回调。
- 调整窗口后返回首页：检查 `App.vue` 的 resize 处理，它会修改浏览器地址。

## 练习前后怎样检查自己的修改

先查看有哪些现存改动。不要把别人或之前任务留下的内容当成自己的练习结果。

```bash
cd /Users/julian/douyin-tailwind
git status --short
git diff -- src/components/BaseFooter.vue src/router/routes.ts
```

新增文件还没被跟踪时，普通 `git diff` 不会显示其内容，要在编辑器中直接检查。需要撤回时，优先撤销自己刚才那几行，不使用整仓库重置命令。

如果做了第 05 项的代码练习，可分别运行类型检查与构建，再按上面的交互验收。项目已有问题可能让检查失败，应记录首个错误和相关文件，不把“命令退出了”当成“通过了”。

```bash
cd /Users/julian/douyin-tailwind
pnpm type-check
pnpm build
```

目前最值得先做的是练习一和练习二。能讲清一个组件的输入输出，再讲清一次请求的来回过程，就已经具备继续读这个项目的基础。
